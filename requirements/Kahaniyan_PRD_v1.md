## 1. Product Overview

### 1.1 Product Summary

Kahaniyan is a web application that serves pre-written, culturally rooted Indian bedtime stories to children aged 3–10 years. Parents select their child's name, age, preferred Indian language, and story theme — the app fetches and personalizes a matching story from its database, displaying it beautifully for the parent to read aloud.

| Field | Value |
|---|---|
| **Product Name** | Kahaniyan |
| **Type** | Web Application (no mobile app in V1) |
| **Target Audience** | Indian parents with children aged 3–10 |
| **Core Value** | Personalized Indian bedtime stories in 10+ native languages |
| **Stage** | V1 — Build, validate, and get first 10 paying users |
| **Timeline** | 4 weeks to launch |
| **Infrastructure Cost** | ₹0 (all free tiers) |

### 1.2 Problem Statement

Indian parents currently have no good digital storytelling product in their native language. Existing apps are English-only or feature Western characters and have zero Indian cultural context — no Panchatantra, no Birbal, no Tenali Raman, no festival-based themes. Stories are generic; the child is never the hero. This creates a gap for a culturally rooted, language-first Indian storytelling product.

### 1.3 Solution

Kahaniyan solves this by providing a curated library of pre-written Indian stories with name personalization. The child's name is dynamically inserted into the story, making them the hero. Stories are written in 10+ Indian languages and rooted in traditional Indian themes.

### 1.4 Unique Differentiators

- 10+ Indian regional languages — not just Hindi or English
- Rooted in authentic Indian cultural themes — Panchatantra, Birbal, Tenali Raman, festivals
- Child is always the hero — name personalization built into every story
- No AI at runtime — stories are pre-written, reliable, and fast
- First mover in Indian-language digital bedtime stories for kids

## 4. Story Database

### 4.1 Approach — Pre-Written Templates

Stories are pre-written and stored in Supabase. They are NOT generated by AI at runtime. This ensures zero API failures, fast load times, and consistent quality. Each story uses `{childname}` as a placeholder which is replaced with the actual child's name at display time.

### 4.2 Story Structure

| Field | Description |
|---|---|
| **id** | Unique story identifier (UUID) |
| **title** | Story title with {childname} placeholder |
| **language** | ISO language code (hi, te, ta, kn, ml, mr, bn, gu, pa, en) |
| **age_group** | 3-4, 5-6, 7-8, 9-10 |
| **theme** | panchatantra / birbal / tenali / festival / moral |
| **body** | Full story text with {childname} placeholder |
| **moral** | One-line moral of the story |
| **reading_time_mins** | Estimated reading time in minutes |
| **created_at** | Timestamp |

### 4.3 Minimum Story Count for Launch

| Language | Target Count |
|---|---|
| Hindi | 10 stories (2 per theme) |
| Telugu | 6 stories (2 per theme) |
| Tamil | 6 stories (2 per theme) |
| Kannada | 4 stories |
| English | 6 stories (2 per theme) |
| Other languages | 2 stories each (10 stories total) |

**Total minimum: 40 stories before launch.**

## 5. User Flow

### 5.1 New User Flow

1. User lands on Kahaniyan homepage
2. Sees headline, demo story preview, and pricing
3. Clicks 'Create a story free'
4. Clerk sign-up modal appears — email or Google
5. After sign-up, redirected to story generator page
6. Fills in name, age, language, theme
7. Clicks 'Get Story'
8. Story is fetched from Supabase and displayed with name replaced
9. User can read on screen
10. Story count decremented (3 free stories/month limit)

### 5.2 Returning Paid User Flow

1. User logs in via Clerk
2. Redirected to generator — no story count limit
3. Generates story → reads on screen
4. Optionally saves to library or downloads as PDF

### 5.3 Upgrade Flow

1. Free user hits 3 story limit
2. 'Upgrade to ₹99/month' prompt shown
3. Razorpay payment page opens
4. After payment, Supabase user record updated to 'paid'
5. User can now generate unlimited stories

## 6. Technology Stack

| Layer | Tool |
|---|---|
| **Framework** | Next.js 14 (App Router) |
| **Styling** | Tailwind CSS + DaisyUI |
| **Authentication** | Clerk |
| **Database** | Supabase (PostgreSQL) |
| **Package Manager** | npm |
| **Deployment** | Vercel |
| **Payments** | Razorpay (added post-launch) |
| **PDF Generation** | react-pdf or jsPDF (V2) |
| **Version Control** | GitHub |

### 6.1 Key Technical Decisions

- No AI API calls at runtime — stories fetched from database only. Eliminates API failures, cost per request, and latency.
- Next.js API routes used for all backend logic — no separate server needed.
- Clerk handles all auth complexity — social login, session management, JWT tokens.
- Supabase Row Level Security ensures users can only access their own saved stories.

## 10. Risks & Mitigations

| Risk | Problem | Mitigation |
|---|---|---|
| Low story variety | Users get repeated stories after a few uses | Write 40+ stories before launch; add 10 new stories monthly |
| Low conversion rate | Free users don't upgrade to ₹99 | Keep free limit at 3 — just enough to feel value, not enough to stay free |
| Language quality | Non-Hindi story quality is poor | Get native speakers to review Tamil, Telugu, Kannada stories before launch |
| No traffic | Nobody finds the app after launch | Post on Twitter, Reddit (r/India, r/indianparenting), Sharechat, WhatsApp groups |
| Competitor launches | Funded competitor enters the space | Move fast, own the Indian-language niche before anyone else does |
